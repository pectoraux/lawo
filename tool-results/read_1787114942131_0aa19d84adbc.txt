  1083→  1083→──────────────────────────────────────────────────────────────────────
  1084→  1084→
  1085→  1085→The following are hard invariants.
  1086→  1086→
  1087→  1087→I1.
  1088→  1088→Core remains domain-agnostic.
  1089→  1089→
  1090→  1090→I2.
  1091→  1091→Country-specific logic lives in packages.
  1092→  1092→
  1093→  1093→I3.
  1094→  1094→Vertical-specific logic lives in packages.
  1095→  1095→
  1096→  1096→I4.
  1097→  1097→Situation-specific logic lives in situation/procedure packages.
  1098→  1098→
  1099→  1099→I5.
  1100→  1100→LLM output is never authoritative legal truth.
  1101→  1101→
  1102→  1102→I6.
  1103→  1103→Every material decision has provenance.
  1104→  1104→
  1105→  1105→I7.
  1106→  1106→Every rule has temporal/version metadata.
  1107→  1107→
  1108→  1108→I8.
  1109→  1109→Community observations cannot masquerade as authority.
  1110→  1110→
  1111→  1111→I9.
  1112→  1112→Private tenant data cannot enter global knowledge without explicit,
  1113→  1113→authorized publication.
  1114→  1114→
  1115→  1115→I10.
  1116→  1116→Packages are independently versioned and deployable.
  1117→  1117→
  1118→  1118→I11.
  1119→  1119→Packages cannot silently mutate kernel semantics.
  1120→  1120→
  1121→  1121→I12.
  1122→  1122→Extensions cannot bypass capability permissions.
  1123→  1123→
  1124→  1124→I13.
  1125→  1125→Historical decisions remain reproducible.
  1126→  1126→
  1127→  1127→I14.
  1128→  1128→Production changes must preserve backward-compatible contracts unless
  1129→  1129→explicitly versioned.
  1130→  1130→
  1131→  1131→I15.
  1132→  1132→Architecture is changed only through an Architecture Change Order.
  1133→  1133→
  1134→  1134→I16.
  1135→  1135→No feature may introduce a new architectural primitive merely because it
  1136→  1136→makes one feature easier.
  1137→  1137→
  1138→  1138→I17.
  1139→  1139→Repeated code across verticals is evidence to improve the kernel or create a
  1140→  1140→shared capability, not evidence to duplicate vertical logic.
  1141→  1141→
  1142→  1142→I18.
  1143→  1143→A hardening sprint may improve implementation but may not redefine architecture.
  1144→  1144→
  1145→  1145→──────────────────────────────────────────────────────────────────────
  1146→  1146→32. ARCHITECTURAL ESCALATION RULE
  1147→  1147→──────────────────────────────────────────────────────────────────────
  1148→  1148→
  1149→  1149→If implementation requires breaking an invariant:
  1150→  1150→
  1151→  1151→STOP.
  1152→  1152→

  1157→  1157→Instead produce:
  1158→  1158→
  1159→  1159→ARCHITECTURE CONFLICT

  1161→  1161→- requested capability
  1162→  1162→- invariant affected
  1163→  1163→- current implementation
  1164→  1164→- proposed alternative
  1165→  1165→- why current architecture is insufficient
  1166→  1166→- smallest possible architectural change
  1167→  1167→- migration impact
  1168→  1168→- backwards-compatibility impact
  1169→  1169→
  1170→  1170→Wait for explicit Architecture Change Order.
  1171→  1171→

  1190→  1190→6. identify contract surface
  1191→  1191→

  1193→  1193→

  1195→  1195→- preserve contracts

  1197→  1197→- avoid speculative abstraction
  1198→  1198→- avoid changing public semantics
  1199→  1199→- avoid new architectural concepts
  1200→  1200→
  1201→  1201→After the sprint:
  1202→  1202→
  1203→  1203→run the entire architecture verification suite.
  1204→  1204→

  1206→  1206→
  1207→  1207→- changes made
  1208→  1208→- invariants checked
  1209→  1209→- contracts verified
  1210→  1210→- regressions detected
  1211→  1211→- performance impact
  1212→  1212→- security impact
  1213→  1213→- migration impact
  1214→  1214→- architectural diff
  1215→  1215→
  1216→  1216→If architecture changed, mark:
  1217→  1217→
  1218→  1218→ARCHITECTURE VIOLATION
  1219→  1219→
  1220→  1220→Do not conceal it.
  1221→  1221→
  1222→  1222→──────────────────────────────────────────────────────────────────────

  1357→  1357→38. IMPLEMENTATION STYLE
  1358→  1358→──────────────────────────────────────────────────────────────────────
  1359→  1359→
  1360→  1360→Prefer:
  1361→  1361→
  1362→  1362→- explicit types
  1363→  1363→- immutable value objects where useful
  1364→  1364→- deterministic functions
  1365→  1365→- pure rule evaluation where possible
  1366→  1366→- dependency inversion
  1367→  1367→- dependency injection
  1368→  1368→- explicit state transitions
  1369→  1369→- idempotent actions
  1370→  1370→- structured errors
  1371→  1371→- observable execution
  1372→  1372→- test fixtures
  1373→  1373→- contract tests
  1374→  1374→- property-based tests where useful
  1375→  1375→
  1376→  1376→Avoid:
  1377→  1377→
  1378→  1378→- magic behavior
  1379→  1379→- hidden global state
  1380→  1380→- singleton-heavy designs
  1381→  1381→- domain logic in UI
  1382→  1382→- domain logic in controllers
  1383→  1383→- implicit cross-tenant access
  1384→  1384→- LLM-dependent core decisions
  1385→  1385→- hard-coded jurisdiction logic in infrastructure
  1386→  1386→- feature-specific hacks in the kernel

  1389→  1389→39. “DON'T REFACTOR SIDEWAYS”
  1390→  1390→──────────────────────────────────────────────────────────────────────
  1391→  1391→
  1392→  1392→When fixing a feature:
  1393→  1393→
  1394→  1394→DO NOT:
  1395→  1395→
  1396→  1396→copy a similar module
  1397→  1397→add a special-case branch
  1398→  1398→create another competing abstraction
  1399→  1399→duplicate the same concept with a slightly different name
  1400→  1400→
  1401→  1401→Instead ask:
  1402→  1402→
  1403→  1403→“Is this genuinely new kernel capability,
  1404→  1404→shared capability,
  1405→  1405→package behavior,
  1406→  1406→or feature-specific behavior?”
  1407→  1407→
  1408→  1408→Put it in the lowest correct layer.
  1409→  1409→
  1410→  1410→The preferred direction is:
  1411→  1411→
  1412→  1412→feature
  1413→  1413→→ package
  1414→  1414→→ shared capability
  1415→  1415→→ kernel
  1416→  1416→
  1417→  1417→Never:
  1418→  1418→
  1419→  1419→feature
  1420→  1420→→ modify kernel semantics
  1421→  1421→
  1422→  1422→unless explicitly approved.
  1423→  1423→
  1424→  1424→──────────────────────────────────────────────────────────────────────
  1425→  1425→40. DEFINITION OF DONE
  1426→  1426→──────────────────────────────────────────────────────────────────────
  1427→  1427→
  1428→  1428→A feature is NOT done merely because:
  1429→  1429→
  1430→  1430→- UI exists
  1431→  1431→- happy path works
  1432→  1432→- tests pass locally
  1433→  1433→
  1434→  1434→Done means:
  1435→  1435→
  1436→  1436→1. architecture is preserved
  1437→  1437→2. contracts are explicit
  1438→  1438→3. security boundaries are tested
  1439→  1439→4. provenance exists
  1440→  1440→5. temporal semantics are correct where applicable
  1441→  1441→6. failure modes are handled
  1442→  1442→7. observability exists
  1443→  1443→8. tests include edge cases
  1444→  1444→9. backwards compatibility is evaluated
  1445→  1445→10. package boundaries are correct
  1446→  1446→11. no hidden coupling was introduced
  1447→  1447→12. architecture tests pass
  1448→  1448→13. documentation matches implementation
